### [逆向 Coway 空气净化器以摆脱云端依赖](https://scottjg.com/posts/2026-11-11-reverse-engineering-my-coway-air-purifier-to-ditch-the-cloud/) ⭐️ 9.0/10

hackernews · scottjg · 11月12日 22:03 · [社区讨论](https://news.ycombinator.com/item?id=50474959)

**「背景」** 现代智能空气净化器普遍依赖云端服务进行控制与状态同步，导致用户失去对设备的完全掌控。作者发现其 Coway 设备在固件中通过明文 HTTP 下载根证书，存在可被中间人攻击的严重漏洞，这为绕过云认证、实现本地控制提供了技术可能。

**「方案」** 作者通过网络抓包（Wireshark）识别出设备与云端通信的协议，利用 binwalk 提取固件并分析其结构，最终发现设备在启动时通过 HTTP 明文下载根 CA 证书，且证书未做完整性校验。基于此，作者构建了本地 CA 并伪造证书，成功劫持设备与云端的通信，绕过认证机制。随后，通过修改固件或部署自定义控制逻辑，实现了完全脱离云端的本地控制，包括开关、模式切换和滤芯寿命监控。整个过程依赖于对网络协议、固件结构和证书信任链的深入理解，且作者明确指出该方法需一定技术门槛，可能影响保修。

**「启示」** 该实践揭示了当前消费级 IoT 设备在安全设计上的严重缺陷——依赖不安全的证书分发机制，使得用户可通过逆向工程实现对设备的完全自主控制，但也警示我们：随着 LLM 等工具普及，厂商未来可能加速采用更复杂的反逆向手段，用户对硬件的控制权正面临新的技术博弈。

### [用 Claude 实现声音定位的实时系统](https://simonwillison.net/2026/Nov/9/mysterious-beeps/) ⭐️ 9.0/10

rss · Simon Willison · 11月9日 23:57

**「背景」** 家中一间储物室中出现间歇性蜂鸣声，因声音间隔长且无法直接定位，手动排查所有箱子效率极低。作者决定借助 Claude Code 构建一个基于多设备麦克风的实时声源定位系统，利用 WebAudio 和 WebSocket 实现跨设备协同，将 AI 从代码生成工具升级为具备持续感知能力的智能代理。

**「方案」** 系统以 Python Web 服务器为核心，通过 WebSocket 将多台设备（手机、平板、笔记本）连接为监听节点，每台设备持续录制 60 秒音频流并运行基于 FFT 与高通滤波的蜂鸣检测算法。当检测到潜在蜂鸣时，服务器触发最低延迟设备发出校准啁啾音，所有监听设备据此对齐音频片段。系统结合 BeepBeep 论文中的双向感知、自记录与采样计数技术，通过测量蜂鸣到达各设备的时间差实现三角定位。作者通过动态代码推送机制（installModule）在不中断运行的情况下实时更新客户端逻辑，支持拖拽粗略定位、回放验证、标记目标蜂鸣、建议新增监听点等交互功能，最终将声源定位精度控制在约 40 厘米内，成功定位到故障的一氧化碳报警器。

**「启示」** 该实践展示了将大语言模型扩展为具备持续感知与自适应控制能力的 AI 代理的新范式——通过实时接入物理世界输入（如麦克风），AI 可自主调整感知策略、迭代优化系统行为，实现从被动响应到主动探索的跃迁。

**「启示」** 在 AI 辅助开发中，信息密度与可读性之间存在张力；通过人类编辑的摘要与 HTML 折叠机制结合，既能保留完整技术细节，又能显著降低认知负荷，提升代码审查体验。

### [SQLite parse\_number\(\)：C 与 Rust 性能对比](https://simonwillison.net/2026/Nov/8/sqlite-parse-number-c-vs-rust/) ⭐️ 9.0/10

rss · Simon Willison · 11月8日 22:26

**「背景」** 在 SQLite 中实现一个能解析带符号、千位分隔符和百分号的数值字符串的自定义函数 parse\_number\(\)，是处理非标准格式数据的常见需求。作者最初尝试用 Rust 实现，发现其性能虽优于标准 C 库，但代码体积远大于 C 版本，引发对底层性能差异的深入探究。

**「方案」** 通过 AI 辅助快速原型设计，作者对比了 C 与 Rust 实现的 parse\_number\(\)扩展。初始 Rust 版本因使用高效解析器（如 strtod）而表现优于 C，但随后采用 Clinger 的快速路径算法重构 C 实现后，性能显著提升：在 200 万行混合数据上，解析时间从 67 纳秒降至 19 纳秒，全面超越 Rust 版本。该优化通过提前判断数字模式、避免冗余解析路径，实现了接近底层硬件的效率，同时保持了 14KB 的极小二进制体积。

**「启示」** 在高性能数值解析场景下，精心设计的 C 语言实现（如 Clinger 快速路径）可超越高度优化的 Rust 库，证明算法级优化比语言选择更能决定性能上限，且在资源受限环境中仍能保持极小的部署开销。
